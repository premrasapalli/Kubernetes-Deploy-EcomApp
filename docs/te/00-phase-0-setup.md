# ఫేజ్ 0 — వర్క్‌స్పేస్ మరియు డాక్యుమెంటేషన్

> ఇది `docs/te/` లో మొదటి ఫైల్. ప్రతి ఫేజ్‌కు ఇలాంటి ఫైల్ ఉంటుంది.
> ఇంగ్లీష్ డాక్యుమెంట్ = టెక్నికల్ నిజం. ఇక్కడ = అదే విషయం తెలుగులో, ఉదాహరణలతో.

## 1. ఈ ఫేజ్‌లో ఏం చేశాం

ఇంకా AWS లో ఏదీ సృష్టించలేదు. ఖర్చు **$0**. ముందుగా ప్రాజెక్ట్ నిర్మాణం
(ఫోల్డర్ స్ట్రక్చర్) మరియు డాక్యుమెంటేషన్ సిద్ధం చేశాం.

```text
Kubernetes-Deploy-EcomApp/   # రిపో రూట్ (ప్రాజెక్ట్ ఇక్కడే)
├── docs/                  # ఇంగ్లీష్ + తెలుగు వివరణలు
│   ├── ARCHITECTURE.md    # డిజైన్, ట్రాఫిక్ ఫ్లో, ట్రస్ట్ మోడల్, ఖర్చు
│   ├── ISSUES.md          # ప్రతి సమస్య నమోదు (ఫార్మాట్‌తో)
│   ├── RUNBOOK.md         # డీబగ్ చేసే కమాండ్లు
│   ├── LEARNINGS.md       # మీ నోట్స్
│   └── te/                # తెలుగు వివరణలు (ఇది ఆ ఫోల్డర్)
├── 01-terraform-eks/      # VPC, EKS, IRSA, ECR (ఫేజ్ 2)
├── 02-app-source/         # మైక్రోసర్వీస్ కోడ్ (ఫేజ్ 1)
├── 03-k8s-manifests/      # Kustomize base/overlays (ఫేజ్ 4)
├── 04-platform/           # Cilium, Gateway API, ESO (ఫేజ్ 3)
└── 05-scripts/            # bootstrap / validate / teardown
```

## 2. ఎందుకు డాక్యుమెంటేషన్ మొదట?

ఎంటర్‌ప్రైజ్‌లో పని చేసేటప్పుడు సమస్యలు తప్పవు. ముఖ్యమైనది "ఎలా ఫిక్స్ చేశాం" కాదు,
"ఎందుకు జరిగింది, ఇదే ఫిక్స్ ఎందుకు మాత్రమే పనిచేస్తుంది" అనేది.

అందుకే `ISSUES.md` లో ప్రతి ఎంట్రీకి ఈ విభాగాలు తప్పనిసరి:

| విభాగం | అర్థం |
|---|---|
| Symptom | ఏమి కనిపించింది (error, logs, HTTP status) |
| Root cause | అసలు కారణం — ఏ కాంపోనెంట్, ఏ కాన్ఫిగ్ |
| Investigation | ఏ కమాండ్లు నడిపాం, ఏమి తెలిసింది |
| Resolution | సరిచేయడానికి చేసిన మార్పులు |
| **Why this only works** | ఈ ఫిక్స్ ఏ డిపెండెన్సీ వల్ల పనిచేస్తుంది |
| Verification | ఫిక్స్ పనిచేసిందని రుజువు |
| Prevention | మళ్లీ రాకుండా గార్డ్‌రైల్ |

"ఫిక్స్ అయింది" అని మాత్రమే రాస్తే, రేపు మళ్లీ అదే సమస్య వస్తుంది. కారణం తెలిస్తేనే
మీరు స్వతంత్రంగా పరిష్కరించగలరు — అదే ఈ ప్రాజెక్ట్ లక్ష్యం.

## 3. ఎందుకు `docs/te/` విడిగా?

- ప్రొడక్షన్ మానిఫెస్ట్‌లలో తెలుగు కామెంట్లు ఎక్కువైతే చదవడం కష్టం.
- ఇంగ్లీష్ డాక్యుమెంట్ = టీమ్/ఇంటర్వ్యూ కోసం; తెలుగు = మీరు లోతుగా అర్థం చేసుకోవడానికి.
- రెండూ ఒకే చోట (`docs/`) ఉండటం వల్ల సింక్ చేయడం సులభం.
- ప్రతి ఫైల్ పైభాగంలో చిన్న తెలుగు బ్లాక్ ఉంటుంది; పూర్తి వివరణ ఇక్కడ ఉంటుంది.

## 4. ఖర్చు గురించి నిజం (మీ free account కోసం)

**EKS ఎప్పుడూ ఉచితం కాదు.** కంట్రోల్ ప్లేన్ గంటకు $0.10 ≈ నెలకు $73.

| అంశం | ల్యాబ్ (ఆప్టిమైజ్డ్) | ప్రొడక్షన్ లాంటిది |
|---|---|---|
| EKS control plane | ~$73/నెల | ~$73/నెల |
| Nodes | 1× t3.medium spot ~$10–12/నెల | 3× m6i.large ~$220/నెల |
| NAT Gateway | లేదు (public subnets) | ~$33/నెల |
| Load Balancer | Cilium LB IPAM (ఉచితం) | NLB/ALB ~$18/నెల |
| EBS | ~$3/నెల | ~$30/నెల |
| **మొత్తం** | **~$85/నెల, సెషన్‌కు ~$5–8** | **~$350+/నెల** |

అంటే: 24×7 వదిలేస్తే నెలకు ~$85. ప్రతి సెషన్ తర్వాత destroy చేస్తే ఒక వీకెండ్‌కు ~$5–8.

**తప్పనిసరి చర్యలు (ఫేజ్ 2 ముందు):**
1. AWS Budgets లో $10, $25 అలర్ట్ పెట్టండి.
2. `05-scripts/teardown.sh` తయారు చేసి, ప్రతి సెషన్ చివర్లో నడపండి.
3. Billing → Cost Explorer లో రోజువారీ ఖర్చు చూడండి.

## 5. ముఖ్యమైన పదాలు (glossary)

| పదం | సులభ వివరణ |
|---|---|
| **EKS** | AWS నిర్వహించే Kubernetes కంట్రోల్ ప్లేన్ |
| **CNI** | పాడ్‌లకు IP ఇచ్చి, వాటి మధ్య నెట్‌వర్క్ నడిపే ప్లగిన్ |
| **Cilium** | eBPF ఆధారిత CNI; నెట్‌వర్క్ పాలసీ, L7, Gateway API కూడా ఇస్తుంది |
| **kube-proxy replacement** | kube-proxy పని Cilium తానే చేయడం (eBPF ద్వారా) |
| **Gateway API** | Ingress తర్వాత తరం; GatewayClass → Gateway → HTTPRoute |
| **IRSA** | IAM Roles for Service Accounts — పాడ్‌కు AWS అనుమతి |
| **ESO** | External Secrets Operator — AWS Secrets Manager నుండి K8s కి సీక్రెట్స్ |
| **PSS** | Pod Security Standards — restricted స్థాయిలో పాడ్ భద్రత |
| **PDB** | Pod Disruption Budget — అప్‌డేట్ సమయంలో కనీస పాడ్‌లు |
| **HPA** | Horizontal Pod Autoscaler — లోడ్ బట్టి పాడ్‌ల సంఖ్య |
| **Hubble** | Cilium ఫ్లో లెవల్ అబ్జర్వబిలిటీ (ఎవరు ఎవరికి కనెక్ట్ అయ్యారు) |

## 6. తదుపరి దశ (ఫేజ్ 1)

మైక్రోసర్వీసెస్ కోడ్ రాయడం:
`frontend`, `product-api`, `cart-api`, `order-api`, `postgres`, `redis`.
అన్నీ చిన్నవి కానీ నిజంగా పనిచేసేవి — తద్వారా నెట్‌వర్క్ పాలసీ, L7, IRSA,
probes, HPA అన్నీ నిజంగా పరీక్షించవచ్చు.

**గుర్తుంచుకోండి:** ఈ ఫేజ్‌లో AWS ఖర్చు లేదు. ఫేజ్ 2 (Terraform apply) ముందు
మాత్రం ఖర్చు నిర్ణయం తీసుకోవాలి.
